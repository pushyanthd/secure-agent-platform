# Run the 400-episode evaluation yourself

The repository now contains forty authored decision templates and four fixed
attacks per template. The release workflow schedules **400 fresh trials**:
40 × (1 clean + 4 attacks) × (baseline + defended).
The release remains experimental. The [corpus scope](held-out-corpus.md) explains
what these new templates do and do not hold out.

## On this prepared Mac

The first session now contains all 400 outcomes and a **FAIL** gate. See the
[September 27 results](evidence/release-v1-2026-09-27/README.md).
Preparation on September 26 passed 600 Python tests and 24 Docker probes.
The execution instructions below describe the original frozen run; preserve it.
The current completion-guard runtime has a different source fingerprint. Use
[the frozen-source regrading command](completion-guard.md#historical-evidence)
to report the completed session; do not resume it with modified source.
After changing validation assets or model behavior, prepare a separately declared
study with new checks, freeze, and session paths.

From the project directory, with Docker Desktop and the pinned model server running:

```sh
cd /Users/pushyanth/Desktop/Code/secure-agent-platform
make release-status
make release-start EPISODES=10
```

The ten episodes are the **first ten of the actual frozen run**, not disposable
practice trials. The command finishes the current session after ten saved outcomes.
Failures remain recorded. No episode is silently retried or discarded.

Continue the same schedule:

```sh
make release-start EPISODES=10   # Another ten, starting where you stopped
make release-start               # Or finish all remaining episodes
```

On macOS, prevent idle system sleep for the duration of a session with
`caffeinate -i make release-start`. Keep the separate model-server terminal open.
If it is not already running, start `make model-serve` in another terminal.
There are no model downloads or paid API calls in these evaluation commands.

Progress prints after each saved episode. Each episode has a 300-second execution
budget, so an individual progress line can take minutes. Historical development
runs suggest allowing an overnight or multi-session run. The first release had a
91.55-second median episode duration, with two episodes reaching 300 seconds;
these timings were measured under uncontrolled host load.

## Pause, inspect, and finish

Press **Ctrl+C once** to finish and save the current episode, then pause. A second
interrupt can stop it immediately; recovery accounts for that interrupted trial
instead of silently generating another answer. Inspect progress from another
terminal without needing inference or changing state:

```sh
make release-status
```

`make release-start` resumes the same named session. It refuses a concurrent
writer and rejects changed source, validation assets, fixtures, model, or runtime.
Keep the checkout, dependencies, model profile, and tool image fixed until the
400 outcomes are recorded. Committing the unchanged files is fine.

After all 400 outcomes are saved:

```sh
make release-report
```

Read `artifacts/release-session/gate.json`, then open
`artifacts/release-session/analysis/explorer.html` in a browser. The results also
include paired intervals, common-clean comparisons, failed tasks, attack exposure,
and runtime diagnostics. PASS exits 0; failed behavioral objectives exit 1;
incomplete or incompatible evidence is UNUSABLE and exits 2. A nonzero gate result
is not permission to remove failures or change the original run.

`make release-report` also prints baseline/defended counts, frozen requirements,
noncompleted trial reasons, and overlapping clean-failure labels. It preserves
the scorer's exit status, so a valid FAIL report still ends with Make's error.
UNUSABLE evidence never prints an old gate's metrics as a fresh result.

## Prepare from a fresh checkout

Install locked dependencies, build the fixed tool image, and explicitly fetch/start
the pinned local model as described in [local setup](local-model.md). Then:

```sh
make release-validate   # 400 authored boundary/grader cases; zero model calls
make release-prepare    # Full checks + Docker probes + corpus checks + freeze
make release-plan       # Create 400 queued trials; zero generation requests
make release-status     # Should show 0 recorded, 400 scheduled
make release-start EPISODES=10
```

Preparation requires the local model server for identity verification, but it
never sends a generation request. Repeating `release-prepare` verifies an existing
matching freeze; it never overwrites it. Repeating `release-plan` preserves the
same schedule. `make release-start` also creates a session if planning was skipped.

`RELEASE_DIR` and `RELEASE_SESSION` override the two default directories when
working with separately declared studies. Preserve the first study and disclose
prior held-out exposure; do not use a new directory to conceal unsuccessful trials.
