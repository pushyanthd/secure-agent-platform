# V1 release checklist

Updated October 7, 2026. The intended release is an **experimental local AI
engineering portfolio project**. The original 400-trial behavioral gate remains
**FAIL**. The architecture plan allows that label with explicit failed objectives;
it does not turn missing operational evidence into verified behavior.

  attacked**, with zero unfinished trials or unresolved attack grades.
- Final publication checksums, documentation links and source whitespace checks pass.

## Remaining before calling the planned V1 work complete

| Work | Completion evidence |
|---|---|
| Newly declared release evaluation | Freeze the selected configuration and evaluation scope before inference; retain all results. The original forty templates are exposed; an untouched holdout claim requires independently authored new tasks. |
| Aggregate artifact storage bound | Configure an enforceable quota and measure exhaustion, retained state and safe recovery. Per-call output/token limits do not establish this. |
| Additional live recovery and cancellation | Inject controlled mid-episode faults/cancellation and account for effects, model calls, recovery and orphan containers. Existing deterministic/scripted tests retain their narrower claims. |
| Measured offline behavior | Observe worker, tool and native-model processes during a run. Container network denial and loopback configuration alone do not establish host-wide absence of public calls. |
| GitHub publication | Review the final diff, commit the release package, pass hosted CI and create the experimental tag/release with the recording and known failures. These steps have not been performed. |

The [resource-completion runbook](resource-completion.md) records the current
bounded treatment: resource-specific required observations with no extra review
calls, expected decision labels or permission grants. A favorable development
result only qualifies a candidate; it does not pass a new release gate or change
the default automatically.

## Scope that stays explicitly limited

The release-scale prompt-only ablation, stronger OS separation between operator
and worker, broader telemetry and independent external reproduction remain open.
An external reproduction requires another reviewer. Historical extracts without
portable SQLite grading state retain their original verification limits.
Additional hardware profiles, multi-seed repeats, external AgentDojo integration,
cloud deployment and dashboards are outside the shortest V1 path.

The [completion audit](portfolio-acceptance.md), [system card](system-card.md) and
[frozen limitations](../evaluations/release-limitations-v1.json) are authoritative
for claim scope. The original gate failed on low utility and two unresolved
attacks; zero observed wins cannot compensate for those failures.
